# @sherpa/npm

Builds the `sherpa-review` npm package (`docs/architecture.md §1`) into `dist/`: `package.json`, `README.md`, `LICENSE`, the IBM Plex font license `LICENSE-IBM-Plex.txt` and `THIRD-PARTY-LICENSES.txt` beside `bin/` with two files. Nothing at runtime reads the repository checkout or calls pnpm.

- `dist/bin/sherpa-review.mjs` is the only command, a thin CLI without the server or UI. The worker loop calls it on every request, so startup must stay fast. `sherpa-review guide` prints the session guide the skill stub (`skills/sherpa-review/SKILL.md`) runs.
- `dist/bin/sherpa-review-server.mjs` is the PR server module with embedded UI assets, not an executable. Only `sherpa-review server` loads it with `import()`. This is the process `sherpa-review up` daemonizes as `node <bin directory>/sherpa-review.mjs server …`. Override the module path with `SHERPA_SERVER_BIN`.

The manifest is generated by `build.mjs`: the version comes from the root `package.json`, there are no dependencies or scripts. `THIRD-PARTY-LICENSES.txt` lists the packages whose code reached the two bundles, taken from the esbuild metafiles of the CLI and server and from `packages/ui/build/bundled-modules.json`, which the UI build writes. The build fails if that list is missing or does not match `packages/ui/dist` (rebuild the UI), or a bundled package has no license. The entire `dist/` directory is a build artifact and is not stored in git.

```
pnpm --filter @sherpa/ui build
pnpm --filter @sherpa/npm build
```

The chain does not build the UI: the server module embeds `packages/ui/dist` and fails with instructions if the UI has not been built. Releasing is `pnpm release` from the repository root (`CONTRIBUTING.md`).
