DECISIONS
  • The arrow shows the direction in which visible context grows: ↑ adds 20 lines at the top edge of the hidden block, ↓ at the bottom. Repeated clicks reveal more, and the counter decreases.
  • An unavailable direction leaves an empty gutter cell instead of a grey placeholder. Empty space doesn't look like a broken button, and the grid stays in place.
  • The ↕ glyph from the old row remains in exactly one case: fewer lines remain than the step size, so a click expands the whole block (one target instead of two).
  • The target is 46×24 (the standard diff gutter size). The counter text isn't clickable because the direction would be unclear.
  • Hover highlights only its half and replaces the counter with the action label, so the step size and direction are visible before clicking.
  • Keyboard: the context gap has one tab stop, ←/→ moves between arrows, Enter loads more. aria-label "Load 20 lines up, 347 hidden".

Delivery rules
  • One sprite file: <symbol id="ic-*">, included once, inserted with <use>. No icon fonts.
  • Rendered sizes: 13px in 11–12.5px text rows, 15px on the Ship button, 9px in an 11×11 box. No intermediate sizes.
  • Colour comes only from the parent's color. In the tokens, the icon is always one shade quieter than the text (#6b7078 against #9ba1ab).
  • Use strokes because filled shapes blur at 13px. The thumb is the exception (its silhouette is only recognisable when filled).
  • aria-hidden on the icon, label on the button (as in SPEC §accessibility).
  • The collapsed chevron uses a separate ic-chev-right instead of the same file rotated by 90°, so its thickness doesn't change during rotation animation.
1c · M5 · №9b

"PR comments" modal

The modal is 620px wide, with existing comments first and the composer below. Drafts and published comments share one list. Drafts have a lighter background, a yellow chip and edit actions. Published comments are immutable. Everything publishes as one batch on Ship, so the modal has no "Publish" button.

Scrolling
  • Only the list scrolls: the header and composer stay fixed at the modal edges. The list uses max-height:330px, then its own scroll with overscroll-behavior:contain (the page beneath the modal stays still).
  • Newest first. Saving a draft scrolls the list to it, clears the composer and keeps the composer in place.
  • Editing happens in place: the pencil turns the list item itself into an editor (same toolbar and layouts), the border turns blue and the chip says "editing". The bottom composer is only for a new comment. Their text stays separate.
  • Deletion takes two steps within the item: the trash icon opens a row saying "Delete draft? It won't be published" with "Delete" / "Keep". There is no modal over a modal. Deletion has no undo, so confirmation is required.
  • The modal grows rather than the list while the viewport height allows: max-height:min(330px, 100vh − 260px). Below a viewport height of 520px, the composer shrinks to 64px.
  • The 26px gradient at the bottom is the only sign that the list continues. The scrollbar is thin, #2b2f36, with a transparent track.

Decisions
  • The toolbar has exactly 6 buttons: B, I, link, inline code, code block, list. No headings, a 3-line comment does not need them.
  • Two layouts for the same field: Visual applies formatting in place, as in the finished comment (default), Markdown shows the same text as source, 12px monospace. The toggle is on the right of the toolbar. The choice is saved per user.
  • The text has one format, markdown. "Visual" edits that same markdown: typing, caret movement, selection, and formatting happen directly in the rendered body (using the renderer for published comments). It is neither a preview nor a second format. The toolbar works in both layouts. In "Visual" it acts at the caret and inserts a placeholder ("text", "code") when nothing is selected. In "Markdown" it wraps the selection in markers.
  • ⌘B/⌘I/⌘K do the same as the buttons. ⌘⏎ = "Save draft", Esc = "Cancel" (with confirmation if the text is not empty).
  • There is no "Send" or "Publish", only "Save draft". Ship alone publishes comments, as the note below the field explains.
