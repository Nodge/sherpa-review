SHERPA · ONBOARDING 2026-09-02

First visit: 8 tips on the live interface

Onboarding uses neither a wizard nor a takeover. The card sits beside a real element, the screen stays undimmed, and the interface remains usable. This extends the principle of a "scrollable document, not a step-by-step wizard". 2a is the step storyboard with final copy. 2b covers card anatomy, the ring, four positions and fallbacks. 2c covers display rules, fallback behaviour, keyboard controls and telemetry. The live tour runs in Sherpa.dc.html, through the "07 · First run" scenario in the dock or a command in the palette.

2a · storyboard

Eight steps

The order follows the reviewer's path, not the menu structure: what to read first (01–03), how to track progress (04), how to change the order and ask questions (05–06), then the way out (07) and finishing (08). Each step attaches to an element that is actually on screen at that moment, so the tour starts once the first stop is ready, not on an empty skeleton.

2c · rules

Display, exit, fallback behaviour

When to show it
Trigger: first visit to the UI, when the first stop is ready (not the skeleton). No tour while generation is in progress.
Once: a per-user flag, not per-PR. Set on completion and on "Skip tour", so dismissing it means it's dismissed.
Unfinished tour: closing the tab at step 03 doesn't count as completion. On the next visit the tour resumes at step 03 (the step is stored in the same key).
No agent (F5): show the tour but leave out step 06, with 07 steps on the counter. If generation fails, don't start the tour at all.
Leaving and returning
Skip tour is a text link on the left of the card footer, at every step. It's the only way to dismiss the tour for good.
Clicking the interface doesn't close the tour. The highlight doesn't block interaction, so the reviewer can try the element and return to the card.
Esc closes the palette but keeps the tour open, so an accidental Esc doesn't use up the only showing.
Returning: the palette command "Replay the onboarding tour · 8 steps", in the sherpa group. Resets the flag and starts at 01.
Keyboard: → / Enter goes forward, ← goes back. Focus moves to the card, and the highlight ring is described in the step's aria description.
Accessibility and telemetry
The card has role="dialog" with aria-modal="false". The screen reader reads the step without trapping focus away from the page.
Step changes are announced in a live region: "step 4 of 8, progress".
Smooth scrolling and card movement are disabled with prefers-reduced-motion.
Events: tour_shown, tour_step (number, time on step), tour_skipped (at which step), tour_completed, tour_replayed. The most frequently skipped step is a signal to rewrite its text, not to remove the step.
OPEN QUESTIONS
1. Where does the completion flag live, locally per-user on Sherpa's disk or in the browser session? On disk it survives a browser change but is lost on reinstallation.
2. Does the second pass need its own small hint (F3, "what changed since last time"), or is that an explanation of the banner beyond onboarding?
3. Step 06 needs an agent. If the agent dies midway through the tour, do we finish without that step or show it with reconnection instructions?
